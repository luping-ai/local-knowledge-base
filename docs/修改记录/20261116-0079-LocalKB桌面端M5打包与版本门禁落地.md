## 2. 产物

```
dist-localkb/LocalKB/                    156.9 MB（解压后）
  LocalKB.exe                              5.2 MB（GUI 子系统）
  _internal/                              运行时 + PySide6 + 解析库
  install-manifest.json                   版本清单

output/LocalKB-0.1.0-win64.zip            65.9 MB
output/LocalKB-0.1.0-manifest.json        清单（含 exe sha256）
```

### 体积：从 225.5 MB 压到 156.9 MB

裁剪掉 68.6 MB，两个大件：

| 文件 | 体积 | 为什么能删 |
| --- | --- | --- |
| `opengl32sw.dll` | 19.7 MB | Qt 的软件 OpenGL 兜底。只用 QWidget（不用 QOpenGLWidget / QQuick）时不需要 |
| `*.onnx` × 16 | 48.9 MB | PyMuPDF 的版面分析/表格识别模型。我们只用 `get_text("dict")` 取文本与坐标（方案 §16 P7 明确 v0.1 不做表格结构化） |

**裁剪必须验证**：这两类文件删错会让某个功能"悄无声息地不能用"。所以脚本里
裁剪之后立刻跑冒烟测试（启动 exe 并等窗口出现），另外 `--self-check` 会真造
PDF/DOCX/XLSX 并解析——只 `import` 不够，PyMuPDF 缺 mupdf 后端时 `import`
成功但 `open` 失败。

## 3. `--self-check`：一个刻意的设计

### 为什么需要它

冻结后的 exe 是黑盒。用户机器上的故障（缺 DLL、某个纯 Python 模块没被
PyInstaller 收进来）只会表现为"双击后闪一下就没了"——没有任何可诊断信息。

自检检查七项：

```
  [OK  ] 依赖导入  PySide6 6.12.0 / openpyxl 3.1.5
  [OK  ] PDF 解析  2 块，页码 [1, 2]
  [OK  ] DOCX 解析  2 块（含标题）
  [OK  ] XLSX 解析  3 块
  [OK  ] 切块器  1 块，chunker localkb-py@1.0.0
  [OK  ] state.db  schema v1
  [OK  ] Runtime 连接  已连接，level=rule_only
  [OK  ] 版本检查（SDK + 契约）  版本检查通过
```

### 为什么结果要写文件 + 弹窗

主 exe 是 **GUI 子系统，没有 stdout**——`print` 的内容直接丢掉。

第一版只 `print`，结果在冻结版里什么也看不到。改法：

1. **始终写** `<数据目录>\selfcheck.txt`（唯一可靠的输出通道）
2. 有 stdout 时同时打印（开发期方便）
3. **最后弹窗**（用户双击 `LocalKB.exe --self-check` 也能看到，不用开 cmd）

第 3 条是为"用户报问题"设计的：让他在快捷方式后面加一个参数、双击、
截图发过来。比让他开 cmd 敲命令现实得多。

## 4. 版本门禁（方案 §13.4）

### 检查什么

| 项 | 判据 | 不满足时 |
| --- | --- | --- |
| SDK 版本 | `>= 0.2.0, < 0.4.0` | **致命**：提示重装 |
| 契约版本 | `schema_version >= 2` | **致命**：提示升级 LocalAIHub |
| RAG 可用 | `rag_enabled` | 警告：提示关程序重启服务 |
| Runtime 连接 | `live()` | 警告：交给 `runtime_conn` 处理 |

### 为什么契约版本用"能力号"而不是 Runtime 版本号

Runtime 版本号是发布节奏（0.2.7、0.3.0…），与"有没有 `page_start` 字段"无关。
锁版本号会让"用户升级服务端"变成"桌面端不能用"（方案 §13.4 已记录过一次
真实事故：运行过期二进制导致 `upload_document` 返回 404）。

契约版本直接对应能力：

| 值 | 含义 |
| --- | --- |
| 1 | Phase 1 之前（无 `documents/chunks`） |
| **2** | 含溯源四列 + `documents/chunks` + `chunker_version`（M1/M2 的依赖） |
| 3 | 含相似检测三表 |
| 4 | 含表格结构化指纹（当前代码为此值） |

### 一个自己踩的坑：上限设成 0.3 会误报

第一版写 `MAX_SDK_VERSION = (0, 3, 0)`，而本项目实际开发用的 SDK 就是 **0.3.0**
——自检一启动就报"桌面端与 SDK 0.3.0 不兼容"，而它明明跑得好好的。

上限的语义是"我验证到 0.3.x 为止，0.4 可能有破坏性改动"，所以应为 `0.4.0`。
教训：**上限要留出当前已适配的版本**。

## 5. 首次引导：只在有问题时出现

方案 §13.3 原文写的是"检查 Runtime → 检查模型 → 选目录…"的多步向导。
实际做成向导有两个问题：

- 用户第二次打开还要再看一遍（或要维护"已完成引导"标记，而那标记会在
  换机器/清数据后失效）
- 每个检查项的状态**随时会变**（模型可能刚被卸载）

所以做成"一次性问题提示"：只在真的有问题时出现，每项独立。状态正常时
什么都不显示。

覆盖两种状态：

| 状态 | 提示与动作 |
| --- | --- |
| 没装 Local AI Hub | 说明"本程序不带运行环境"+ 为什么这样设计（单实例锁）+ 「重新检查」 |
| 装了但没模型 | 「打开管理后台」+ 说明推荐哪个模型 + 「重新检查」/「稍后」 |

**"稍后"必须可用**：用户可能只是想先看看界面、整理目录。弹一个必须解决的
对话框会拦住这些事；选"稍后"后问题写进对话页黄条，随时能再处理。

## 6. 端到端验证

### 从干净解压目录运行

```
$ Expand-Archive output/LocalKB-0.1.0-win64.zip -DestinationPath $TEMP\localkb-clean-test
$ .\LocalKB.exe --self-check
```

```
  [OK  ] 依赖导入  PySide6 6.12.0 / openpyxl 3.1.5
  [OK  ] PDF 解析  2 块，页码 [1, 2]
  ...
  [OK  ] 版本检查（SDK + 契约）  版本检查通过
全部通过
```

**注意 `level=rule_only`**：当时内存紧张（残留引擎占满）。这正好验证了
服务端待办 S13 的修复——知识库端点仍然可用（`docs:3 chunks:296`），
而修复前会全部 404。

### GUI 冒烟

`package-localkb.ps1` 的 `[3/5]` 步骤会启动 exe 并等主窗口出现，
超时或提前退出即失败。这能抓到"缺 DLL 导致启动崩溃"这类问题。

| **图标** | ⏳ 未做 | 需要 `.ico` 素材 |

### 为什么不用 mksfx（自解压 exe）

仓库既有 `tools/mksfx` 是为 Runtime 做的（Go stub + 内嵌 payload）。对桌面端，
同样做法需要再写一个 Go stub——而"为解压一个文件夹多维护一个二进制"不值得。

先用 zip：用户解压后双击 `LocalKB.exe` 即可用。内测够用；真正需要安装向导
时再上 Inno Setup（它比自研 stub 更可靠，且支持卸载项/开始菜单/文件关联）。
